# Structured Output

Declare an `output` block to make an agent return a validated object instead of free text. It uses the same DSL as a tool's [`input`](/docs/tools#input-schema-dsl):

```ruby
class InvoiceAgent < OmniAgent::Agent
  use_model "gpt-4o-mini"

  output do
    string :invoice_number, description: "Invoice identifier as printed"
    number :total, min: 0
    enum :currency, values: %w[USD EUR]
    array :line_items do
      string :description
      number :amount
    end
  end
end

response = InvoiceAgent.new.run(invoice_text)
response.structured_output
# => { invoice_number: "A-1042", total: 120.5, currency: "USD", line_items: [ { description: "Paper", amount: 120.5 } ] }
response.answer # the raw JSON string returned by the model
```

## How It Works

1. The schema is sent to the provider with every request. OpenAI and Ollama receive it as a `json_schema` `response_format`.
2. When the model gives its final answer, the JSON is parsed (a surrounding ` ```json ` fence is tolerated) and validated with the same rules as tool input: required fields, `enum` values, `min`/`max`, `min_length`/`max_length`, `pattern`, `min_items`/`max_items` and custom `validate:` procs. Keys not declared in the schema are dropped.
3. The result is exposed as `response.structured_output`, a hash with symbol keys. It is set before `after_generation` callbacks run, so callbacks can read it from `payload[:response]`.

If the model returns invalid JSON or the object fails validation, `run` raises `OmniAgent::StructuredOutputError`.

Like tool input, validation applies to top-level fields; nested objects are described to the model but not validated field by field.

## Strict Mode

OpenAI's strict structured outputs are enabled automatically when the schema allows it: every field is required, every `hash` has a block, and no `min_length`/`max_length` is used. Otherwise the schema is sent with `strict: false`, so the model follows it as guidance and OmniAgent's validation enforces it.

## Inheritance

`output` is inherited by subclasses, and a subclass can declare its own `output` block to replace it. This is how [stock agents](/docs/stock-agents) let each project decide which fields to extract.

## Mock Provider

With `provider :mock`, an agent that declares `output` gets placeholder JSON that satisfies the schema (the first `enum` value, `min` for numbers, lorem ipsum for strings), so you can wire up code that reads `structured_output` before calling a real model.
