# Authentication

An MCP server mounted over HTTP lets anyone who can reach the URL run your tools. For that reason, **every server must declare `authenticate`**. A server without it raises `OmniAgent::MCPError` on the first HTTP request. To make a server public on purpose, write `authenticate :none`.

Authentication returns a **principal**: the identity of the caller. The principal is passed to [`authorize_tool`](./defining-servers.mdx#per-principal-tool-access), to the [`context`](./defining-servers.mdx#tool-context) block, and to tools as `context[:mcp_principal]`.

Requests that fail authentication get `401 Unauthorized` with `WWW-Authenticate: Bearer realm="<server_name>"`. [OAuth 2.1](#oauth-21) servers add more detail to that header.

## Static Bearer Tokens

```ruby
authenticate :bearer, tokens: -> { ENV.fetch("SUPPORT_MCP_TOKENS", "").split(",") }
```

Clients send `Authorization: Bearer <token>`. `tokens:` accepts:

* **An Array**: Any listed token is accepted. The principal is `:bearer_token`.
* **A Hash of `principal => token`**: The principal is the matching key. Use it to tell callers apart:

  ```ruby
  authenticate :bearer, tokens: -> { { "ci" => ENV["CI_MCP_TOKEN"], "ops" => ENV["OPS_MCP_TOKEN"] } }
  ```

* **A Proc that returns either of the above**: The proc runs on every request, so you can rotate tokens in the environment or in credentials without restarting the server. Use a proc whenever you read tokens from `ENV`.

Tokens are compared with `ActiveSupport::SecurityUtils.secure_compare`. Every configured token is checked, with no early exit. Blank tokens are ignored, so an unset environment variable never matches an empty `Authorization` header.

## Custom Authentication

Pass a block to authenticate against your own data. The block receives an `OmniAgent::MCP::Request` (a `Rack::Request` that also has `#bearer_token`). Return the principal, or `nil`/`false` to reject the request:

```ruby
authenticate do |request|
  User.find_by(api_token: request.bearer_token)
end
```

The returned user is then the principal everywhere:

```ruby
authorize_tool { |tool_class, user| user.admin? || !tool_class.tags.include?(:admin) }
context { |user, _request| { current_user: user } }
```

## OAuth 2.1

`authenticate :oauth` implements the [MCP authorization specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization). Your MCP server is an OAuth 2.1 **resource server**: an external **authorization server** (Auth0, Keycloak, Okta, Entra ID, WorkOS, Doorkeeper, ...) signs users in and issues access tokens, and OmniAgent validates those tokens on every request. MCP clients such as Claude Code, Claude Desktop and the MCP Inspector discover the authorization server and run the OAuth flow by themselves, so users never copy tokens by hand.

```ruby
class SupportServer < OmniAgent::MCP::Server
  authenticate :oauth,
               resource: "https://app.example.com/mcp/support",
               authorization_servers: "https://auth.example.com",
               scopes: %w[mcp:tools],
               jwks_uri: "https://auth.example.com/.well-known/jwks.json" do |access_token, _request|
    User.find_by(oauth_subject: access_token.subject)
  end
end
```

OmniAgent does not include an authorization server. Use your identity provider, or a gem such as Doorkeeper in your app. The MCP specification expects it to support PKCE and to accept the `resource` parameter ([RFC 8707](https://www.rfc-editor.org/rfc/rfc8707)), so that tokens name your server as their audience.

### Options

* **`resource:`** (required): The canonical URL of this MCP endpoint, as clients connect to it. Tokens must list it in `aud`. It is configured rather than read from the `Host` header, so a token for another server cannot be replayed by changing that header.
* **`authorization_servers:`** (required): One or more issuer URLs. They are published in the metadata, and a token's `iss` must be one of them.
* **`scopes:`**: Scopes every token must have. Defaults to none. A valid token that lacks one gets `403` with `error="insufficient_scope"`.
* **`scopes_supported:`**: Scopes advertised in the metadata. Defaults to `scopes:`.
* **`audience:`**: Accept this `aud` value instead of `resource:`. Use it when your authorization server issues a fixed API identifier (for example `api://support`).
* **Exactly one way to validate tokens**: `jwks_uri:`, `introspection:` or `verify_token:`. See below.

`resource:`, `authorization_servers:`, `audience:` and the `introspection:` values also accept a Proc, which runs on every request:

```ruby
authenticate :oauth, resource: -> { ENV.fetch("SUPPORT_MCP_URL") }, ...
```

### Validating Tokens

**JWT access tokens** ([RFC 9068](https://www.rfc-editor.org/rfc/rfc9068)), checked against the authorization server's public keys. Add `gem "jwt"` to your Gemfile:

```ruby
authenticate :oauth, ..., jwks_uri: "https://auth.example.com/.well-known/jwks.json"
```

The signature, `exp`, `nbf` and `iss` are checked. Tokens must contain `exp` and `iss`. Only asymmetric algorithms (`RS*`, `PS*`, `ES*`) are accepted; change them with `algorithms:`. The key set is cached for 5 minutes. A token with an unknown `kid` refetches it (key rotation), at most every 30 seconds.

**Token introspection** ([RFC 7662](https://www.rfc-editor.org/rfc/rfc7662)), for opaque tokens. Every request asks the authorization server whether the token is active:

```ruby
authenticate :oauth, ...,
             introspection: {
               url: "https://auth.example.com/oauth/introspect",
               client_id: -> { Rails.application.credentials.mcp_client_id },
               client_secret: -> { Rails.application.credentials.mcp_client_secret }
             }
```

**Custom verification**, when you already have the logic. The block receives the raw token (and, optionally, the request) and returns the token's claims as a Hash, or `nil` to reject it:

```ruby
authenticate :oauth, ...,
             verify_token: ->(token) {
               record = OAuthToken.active.find_by(digest: Digest::SHA256.hexdigest(token))
               record && { "sub" => record.user_id.to_s, "aud" => record.resource,
                           "scope" => record.scopes, "exp" => record.expires_at.to_i }
             }
```

Whatever the method, OmniAgent then checks the claims: `aud` must contain `resource:` (or `audience:`), `exp` and `nbf` must be current (30 seconds of clock skew allowed), `iss` (if present) must be one of `authorization_servers:`, and `scope` (or `scp`) must contain every scope in `scopes:`. If the authorization server cannot be reached, the request gets `401` and the error is logged.

### The Principal and the Access Token

The validated token is an `OmniAgent::MCP::OAuth::AccessToken`, with `#subject`, `#client_id`, `#issuer`, `#audience`, `#scopes`, `#scope?(*names)`, `#expires_at` and `#claims`.

Without a block, the access token is the principal. With a block, the block's return value is the principal; return `nil` to reject the request. Either way, the token is available as `access_token` inside `authorize_tool` and `context`, and to tools as `context[:mcp_access_token]`. Use it to require extra scopes for some tools:

```ruby
authorize_tool { |tool_class, _user| !tool_class.tags.include?(:admin) || access_token.scope?("mcp:admin") }
```

### Discovery

Clients find the authorization server through Protected Resource Metadata ([RFC 9728](https://www.rfc-editor.org/rfc/rfc9728)). OmniAgent serves it under the endpoint, with no authentication and with CORS enabled for browser-based clients:

```bash
curl https://app.example.com/mcp/support/.well-known/oauth-protected-resource
```

```json
{
  "resource": "https://app.example.com/mcp/support",
  "authorization_servers": ["https://auth.example.com"],
  "scopes_supported": ["mcp:tools"],
  "bearer_methods_supported": ["header"],
  "resource_name": "support"
}
```

Responses that reject a token point clients to it:

| Case | Status | `WWW-Authenticate` |
|---|---|---|
| No token | `401` | `Bearer realm="support", resource_metadata="https://app.example.com/mcp/support/.well-known/oauth-protected-resource", scope="mcp:tools"` |
| Invalid, expired or wrong-audience token | `401` | Same, plus `error="invalid_token"` |
| Missing scope | `403` | Same, plus `error="insufficient_scope"` |

Tokens are only read from the `Authorization` header, never from the query string.

## No Authentication

```ruby
authenticate :none
```

Every request is accepted and the principal is `nil`. Use this only for servers that are not reachable from outside your machine or network, or for tools that are safe for anyone to run.

## stdio

The stdio transport runs as a local subprocess that the MCP client starts. It already has your shell's access, so it does **not** run `authenticate`. Use `stdio_principal` to choose who the local caller is:

```ruby
stdio_principal { User.find_by(email: ENV["MCP_USER_EMAIL"]) }
```

The block runs once when the process starts. Without it, the principal is `nil`. `authorize_tool` and `context` still apply over stdio.

## Origin Checks

Browsers send an `Origin` header. A malicious web page can use DNS rebinding to make a browser send requests to a server on `localhost`. For this reason, the MCP specification requires servers to check `Origin`. OmniAgent rejects requests that have an `Origin` header that is not in the allowlist with `403 Forbidden`. Requests without an `Origin` header are allowed. CLI and desktop clients do not send one.

If a browser-based client must call your server, allow its origin on the server or globally:

```ruby
class SupportServer < OmniAgent::MCP::Server
  allowed_origins "https://inspector.example.com", %r{\Ahttps://.*\.mycompany\.com\z}
end

OmniAgent.configure do |config|
  config.mcp_allowed_origins = [ "https://inspector.example.com" ]
end
```

## Security Checklist

* Serve the endpoint over **HTTPS** in production. Bearer tokens in plain HTTP can be read by anyone on the network.
* Give each client its own token (Hash form) so you can revoke one without affecting the others.
* Hide destructive or expensive tools (such as [exposed agents](./defining-servers.mdx#exposing-agents)) with `authorize_tool`.
* Tool error messages are returned to the client. Do not put secrets in exception messages.
* Request bodies larger than `mcp_max_request_bytes` (default 1 MiB) are rejected with `413`. See [Configuration](/docs/configuration).
* With [OAuth 2.1](#oauth-21), set `resource:` to the exact public URL of the endpoint, and keep `scopes:` minimal.
